# Agent 执行边界测试矩阵

> 场景测试用脚本化模型驱动**真实 TaskService + 真实工具 + 真实临时工作区**，断言落在「模型看到了什么」「文件最终是什么」「事件序列是什么」三处，而不是某个函数返回值。

## 为什么这样测

Agent 没有单一返回值。它做决策、调工具、观察、重试，最后给出一个**主张**。值得验证的性质是关于轨迹与产物的：

- 它是否在断言前真的读过数据？
- 它是否在该停的时候停？
- 它是否越过了被授予的能力？
- 工作区最终状态是否与它声称的一致？

单点单测答不了这些。`tests/support/agent-scenario.ts` 提供场景框架。

## 已覆盖的边界

| 边界 | 场景 | 断言的不变量 |
| --- | --- | --- |
| 证据优先 | 读文件后回答 | 工具结果必须进入模型上下文 |
| 写入真实生效 | 写文件后声明完成 | 文件内容与磁盘一致，非仅口头声明 |
| 能力最小化 | 无写权限时尝试写入 | 文件不得存在 |
| 无证据断言 | 未读文件直接回答 | 上下文里不含该文件内容，且无工具执行事件 |
| 路径逃逸 | 读取 `../../etc/passwd` | 记为 `tool_failed / path_escapes_root`，主机内容不进入模型 |
| 写入逃逸 | 写到 `../escape.txt` | 不产生文件，工作区保持干净 |
| 迭代预算 | 模型无限调工具 | 在预算处失败，调用次数不超预算 |
| 单轮工具上限 | 一轮 3 个调用（上限 2） | 显式失败，不静默截断 |
| 工具失败传播 | 工具抛错 | 失败文本进入上下文，模型可据此报告 |
| 单轮直答 | 无工具回答 | 恰好 1 次模型调用，无工具事件 |
| 持久轨迹 | 两次工具调用 | 每次执行独立落库，且只存 digest |
| 嵌套目录 | 读 `docs/guide.md` | 根内子路径允许 |
| 多轮状态传递 | 列表→读→写→答 | 早期步骤的文件名与取值在末轮仍在上下文 |
| 自愈 | 读错路径后改读正确路径 | 一次失败后仍能恢复并拿到正确内容 |
| 结果分页 | 读取大文件 | 载荷有上限，且给出 offset 续读提示 |
| 连续写入 | 两次写入 | 两个文件都落盘 |

## 尚未覆盖（诚实记录）

- **并行工具调用**：当前 Runtime 按顺序执行，尚未有并发语义可测。
- **真实模型的行为质量**：脚本化模型证明 Runtime 正确，不证明真实模型的判断力；后者需要 `scripts/probe-agent-chat.mjs` 这类真机探针，属手工验证。
- **跨重启的任务续跑**：当前设计是中断后显式重试，恢复语义由 `persistence-conformance` 覆盖，不在场景层重复。
- **审批等待的可视化轨迹**：由 `agent-approval.test.ts` 与 `agent-chat-tools.test.ts` 覆盖，不在场景层重复。
