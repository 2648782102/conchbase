# Agent memory：外部参考与海螺取舍

> 本文是设计输入，不是契约事实源。契约以 ADR 0083 与代码为准。

## 参考对象

### OpenAI Codex CLI

- `AGENTS.md` 是仓库内的分层指令文件：从仓库根到当前目录逐层拼接，越靠近工作目录优先级越高。
- 上下文是“每次重新装配”的：系统指令、环境信息、AGENTS.md、工具定义、历史记录按固定顺序组成提示词前缀，而不是持久化一份不断增长的对话。
- 上下文接近上限时做**压缩**：保留近期消息与关键产物，把较早内容总结成一段交接摘要，且摘要本身被声明为“不要据此重新开始工作，仅作延续参考”。
- 教学要点：固定前缀 + 显式优先级 + 压缩交接，而不是无限追加历史。

### Claude Code

- `CLAUDE.md` 是人工编写的项目记忆，启动时自动加载；支持从当前目录向上递归查找。
- 另有让模型自己维护的 `MEMORY.md`：一个**索引**，每条记忆一行，指向详细文件；启动时只加载索引，需要时才按需读取正文。
- 教学要点：记忆要有“索引/正文”两级，索引小到可以全量注入，正文按需展开；写入走明确规则而不是自由追加。

### 其他同类实践（通用结论）

- 记忆必须是**可审计、可删除**的显式条目，而不是模型随手写的自由文本。
- 记忆需要**作用域**：会话级、项目级、用户级，混合会导致错误迁移。
- 写入必须发生在**有证据的时刻**（一次任务结束、一次明确纠正），而不是每轮对话都写。

## 海螺为什么不能照搬

1. 海螺没有“仓库里的 AGENTS.md”这一层：Project 是 Runtime 对象，不是目录。因此作用域应映射为 `session` / `project` / `runtime`。
2. 海螺已经是事件溯源 + 私有 SQLite 的单一写入方，记忆不应另建文件系统，否则出现第二个事实源。
3. 海螺的模型输出是**不可信输入**。任何让模型“自己写记忆”的设计都必须经过 Runtime 校验、去重、限额，且不能携带明文密钥。
4. 海螺的核心承诺是“用户只跟一个老板对话”。因此记忆的首要消费者是老板 Agent，必须能在**跨项目**时召回，而不是只服务单个会话。

## 海螺的取舍

- 采用 Codex 的“固定前缀”思想：记忆以**有界、按优先级排序的索引**注入提示词，位置固定在组织事实之前。
- 采用 Claude Code 的“索引 + 正文”两级：索引进提示词，正文按需通过既有读取路径展开。
- 拒绝“每轮自动摘要写入”：写入只发生在收敛、明确纠正、用户显式要求三种时刻。
- 拒绝把记忆存成自由文本文件：仍存私有 SQLite，由 Runtime 唯一写入。
- 记忆不授予任何能力，不改变工具许可，不进入公开 API 的权限判断。
